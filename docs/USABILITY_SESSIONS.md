# MVP usability session protocol

Status: protocol ready; 0 of 5 observed student sessions completed.

Use this same protocol for five students before the limited beta. Do not prefill outcomes. Remove direct identifiers from notes and ask participants not to enter real sensitive financial information in a local or demonstration environment.

## Session setup

- Use the hosted beta when available; use the local stack only for internal dry runs.
- Start with an empty test account unique to the participant.
- Record timestamps, task completion, errors, and the participant's words only with consent.
- Do not coach unless the participant is blocked for two minutes. Record any help given.
- After each session, delete the test account and confirm the profile is no longer accessible.

## Tasks

1. Explain what you believe Pathaid does from the landing page.
2. Create an account and complete the initial profile without entering real sensitive data.
3. Find one opportunity that appears useful and explain why it was recommended.
4. Explain the difference between “likely eligible,” “needs more information,” and actually receiving an award.
5. Answer one progressive follow-up question and describe what changed.
6. Open an opportunity, identify its source and last verification information, and use its checklist.
7. Reach the official provider/application page.
8. Edit one profile answer, return to discovery, and then delete the account.

## Success measures

- Core journey completion: at least 4 of 5 participants complete tasks 2–7.
- Result comprehension: all 5 distinguish estimated application eligibility from provider selection.
- Time to first useful result: median under five minutes.
- Privacy comprehension: each participant can identify why a sensitive question is asked and can skip or remove it.
- Accessibility: keyboard-only completion and visible focus are checked in at least one session; assistive technology used by a participant is recorded when applicable.
